# LB-311: load balancer dropped idle keep-alive connections

**Status:** resolved 2026-10-20.

**Infra:** Load balancer firmware 9.4 is rolled out to every region. Idle
keep-alive connections now stay open until the client closes them, and we have
seen no resets from the load balancer since the rollout.

**Payments (Ines):** Please remove the client-side retry in `submit_charge`
rather than keeping it "just in case". Our version of the charges API has no
idempotency keys. When a connection resets *after* the API accepted the
charge, the retry charges the card a second time. That has happened three
times this quarter (all refunded). Surface the error instead: checkout already
shows "payment status unknown" for `ChargeFailed`, and support reconciles
those from the payments dashboard.
