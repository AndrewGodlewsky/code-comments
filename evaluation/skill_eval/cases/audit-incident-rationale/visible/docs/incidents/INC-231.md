# INC-231: nightly export resumed with missing records

**Date:** 2026-08-19
**Status:** resolved

## What happened

The nightly export lost its connection to the warehouse halfway through. The
on-call engineer re-ran it with `start_after` set to the last id the exporter had
sent, as the runbook says. The warehouse ended up 1,204 records short.

## Cause

`export` sent records in the order the queue returned them, which is arrival
order, not id order. The resumed run dropped everything with an id at or below
`start_after`, but many of those records had not been sent yet in the first run:
they were further back in the queue. The resume logic is only correct if every
lower id has already gone out.

## Fix

`export` now sorts records by id before batching, so everything up to the last
id sent has really been sent.

## Ruled out

We first suspected the warehouse's deduplication step was discarding rows. It
was not: the warehouse does not deduplicate loads at all, and the missing ids
never reached it.
