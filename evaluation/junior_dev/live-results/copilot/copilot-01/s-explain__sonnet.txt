Placing an order goes through `place_order(customer, items, card_token)` in `src\app.py`. I haven't run it, and I changed no files.

1. **Stock check.** For each item, it compares the requested quantity with the in-memory `STOCK` dict (mug 12, shirt 3, poster 0). If stock is short, it returns `{"status": "rejected", "reason": "out of stock: <item>"}`. An item that isn't in `STOCK` counts as 0 in stock.
2. **Total.** `total(items)` adds up `PRICES[name] * qty` in cents. An item missing from `PRICES` would raise a `KeyError`.
3. **Payment.** `charge(card_token, total)` in `src\payments.py` returns `{ok, id}`. It is a stub. It fails only when `card_token` is empty. Otherwise it succeeds with a fake `pay_<hex>` id. A failure returns `{"status": "rejected", "reason": "payment failed"}`.
4. **Stock decrement.** After a successful payment, it subtracts the quantities from `STOCK`. This lives only in memory, so it resets when the process restarts.
5. **Recording.** It reads `data\orders.json`, or starts an empty list if the file is missing. It appends `{id, customer, items, payment}`, with `id` equal to the list length plus 1. It writes the file back and returns `{"status": "placed", "order": ...}`.

**Gaps:**
- The README says orders come in through `POST /orders` and that an email receipt is sent. I found no HTTP route and no email code in what I read.
- The read-then-write of `orders.json` isn't protected against concurrent orders.
