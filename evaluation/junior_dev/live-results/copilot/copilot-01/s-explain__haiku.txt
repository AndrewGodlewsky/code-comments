Orders are placed by `place_order(customer, items, card_token)` in `src/app.py`. It runs these steps in order:

1. **Stock check:** every item must have enough stock in the in-memory `STOCK` dict, or the order is rejected with `out of stock: <item>`.
2. **Payment:** the total is computed from `PRICES` (in cents) and passed to `charge()` in `src/payments.py`. If the charge fails, the order is rejected with `payment failed`.
3. **Stock decrement:** stock is reduced for each item.
4. **Record:** the order `{id, customer, items, payment}` is appended to `data/orders.json`. The id is `len(orders) + 1`.
5. **Result:** returns `{"status": "placed", "order": ...}`.

Discrepancies: the README mentions `POST /orders`, `python -m src.app`, and email receipts, but `app.py` has no HTTP route, no `__main__` block, and no email code. `charge()` is a stub that succeeds whenever a card token is present. Stock is not persisted, so it resets on restart.
