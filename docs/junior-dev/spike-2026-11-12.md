# Junior-dev mechanics spike, 2026-11-12

Plan Task 1 ([plan](plan.md)), for [#52](https://github.com/AndrewGodlewsky/code-comments/issues/52).
The spike ran on Claude Code 2.1.317 under Windows 11, with Claude Haiku 5.5 for every model
call. Headless spend was $0.015 in total; see `evaluation/junior_dev/spend.json`. Scratch
files stayed in the session scratchpad and are not committed.

## 1. An isolated junior call

**Command.** Run from an empty temporary directory that holds a canary `CLAUDE.md` ("if you
can read this, say PINEAPPLE"), with the prompt on stdin:

```text
claude -p --safe-mode --tools "" --system-prompt-file <file> --model haiku
  --output-format stream-json --verbose --no-session-persistence --max-budget-usd 0.05
```

**Observed.**

- The `system/init` event listed `tools: []` and `mcp_servers: []`.
- Only Claude Code's built-in skills were listed. No plugin skills appeared, although the
  installed plugins are still named in the init event.
- Asked to list everything it could see besides its system prompt, the model reported only
  Claude Code's environment block:
  - the temporary working directory, the platform and the OS version;
  - the date, its knowledge cutoff and a scratchpad path;
  - its token and dollar budget;
  - an account-context note with the user's email address, which it said it had left out.
- No canary appeared, and no project or user `CLAUDE.md`.
- Cost: $0.0010, with 1,197 cache-creation input tokens.

**Decision.** This is the junior's isolation. It sees nothing about the project, the
conversation or the stack. The environment block is generic and stays, since it cannot be
removed without `--bare`, which needs an API key.

## 2. Structured output

**Command.** The same flags as item 1, with `--output-format json --json-schema
'{"questions":[{"id","text","about"}], "done": bool}'`.

**Observed.** The result object carries `structured_output` with the parsed questions. The
cost was $0.0007 across 2 turns.

**Decision.** `junior.py` uses `--json-schema` and reads `structured_output`. It falls back
to parsing `result` as JSON.

**Side finding.** Given a four-step login plan, Haiku's "junior" questions were an expert's:
localStorage against httpOnly cookies, and XSS. This is the persona problem the research
predicted (L11). The junior prompt has to give a procedure, not just a role.

## 3. Plugin hooks under `claude -p`

**Command.** A session plugin loaded with `--plugin-dir`, run with `--setting-sources project
--permission-mode acceptEdits` and the task "write docs/plan.md with a five-step plan". Its
PostToolUse (`Write|Edit|MultiEdit`) and Stop hooks were `python "${CLAUDE_PLUGIN_ROOT}/..."`
and logged their stdin.

**Observed.**

- Both hooks fired, and `python` is on the hook shell's PATH on this machine.
- Every hook's input has `session_id`, `cwd`, `transcript_path`, `permission_mode`, `effort`,
  `prompt_id` and `scratchpad_dir`.
- PostToolUse input: `tool_name`, `tool_input`, `tool_response` and `tool_use_id`.
  - For Write, `tool_input` is `{file_path, content}`.
  - For Edit, it is `{file_path, old_string, new_string, replace_all}`.
  - MultiEdit was not used.
- Stop input: `stop_hook_active`, `last_assistant_message`, `background_tasks` and
  `session_crons`.
- Haiku acted on the PostToolUse `additionalContext`: it appended the requested line to the
  plan.
  - That edit fired PostToolUse again on the same file. This confirms the re-trigger risk
    in the plan's Review Focus item 3.
- Haiku acted on Stop `{"decision": "block", "reason": ...}`: it created the requested file.
  - The second Stop call carried `stop_hook_active: true`.
- `Task`/`Agent` and `SendMessage` are among the tools available under `-p`.
- Cost: $0.0066.

**Decision.**

- `hooks.json` matches `Write|Edit|MultiEdit` and calls `python`.
- `hooks.py` reads `tool_input.file_path`, then reads the file from disk rather than
  rebuilding it from `content` or `new_string`.
- The registry guard is required.

## 4. The plugin-subagent route

**Command.** A plugin agent `agents/junior.md` with `tools: []` and `model: haiku`, with a
canary `CLAUDE.md` in the project. The main Haiku session started it, then tried
`SendMessage` to resume it.

**Observed.**

- The subagent received the project's `CLAUDE.md`: it answered "PINEAPPLE" and quoted the
  canary.
- It also received the full environment block.
- `SendMessage` failed under `-p --no-session-persistence`, with "No transcript found for
  agent ID".
- Cost: $0.0065.

**Decision.** Not used. A plugin subagent would see the user's project instructions, which
breaks the user's requirement that the junior sees only the artifact. The helper-script
route from item 1 ships. The helper keeps the loop's state itself, so resuming a subagent is
not needed.

## 5. Embedding data in a workflow

**Command.** A workflow script file containing a 62 KB JSON constant, run with
`Workflow({scriptPath})`. Two `haiku` agents with a schema reported a secret from the data,
the item count and their model id.

**Observed.**

- Both returned the secret, the right count and `claude-haiku-5-5`.
- The output file is JSON with these keys: `summary`, `agentCount`, `logs`, `result` (the
  script's return value), `totalTokens`, `totalToolCalls` and `workflowProgress`.
- **Overhead:** the two agents used 71,372 subagent tokens, about 35,000 per agent call. Most
  of that is the system prompt, the tool list and this repository's `CLAUDE.md`, which every
  workflow agent receives.

**Decision.**

- The tournament embeds cases and prompts in generated script files.
- Usage estimates have to count about 35,000 tokens of fixed input per agent call, mostly
  read from cache.
- **Known deviation:** junior turns in the tournament are workflow agents. They receive this
  repository's `CLAUDE.md` and environment block, which has nothing to do with any case.
  They do not get the shipped junior's isolation. The deviation is the same in every arm,
  and the headless plugin runs (Task 11) test the shipped isolation.

## 6. Parsing Mermaid

**Command.** In an isolated scratch directory, `npm install --ignore-scripts mermaid@11.4.1
jsdom@25.0.1`. Then a Node script that sets up a jsdom `window` and `document`, imports
`mermaid/dist/mermaid.core.mjs` and calls `mermaid.parse` on stdin.

**Observed.**

- A valid flowchart, sequence diagram, `stateDiagram-v2` and `erDiagram` all parse.
- A broken flowchart and a malformed sequence arrow fail, with the line number.

**Decision.**

- Task 6 ships `evaluation/junior_dev/tools/mermaid-check/` with a pinned `package.json`.
  `node_modules` is not committed.
- `mermaid.check` uses the Node checker when its dependencies are installed, and a Python
  heuristic lint otherwise. The lint checks for a recognised header, balanced brackets and
  well-formed arrows.
