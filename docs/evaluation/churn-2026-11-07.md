# Unnecessary code churn: Haiku vs Sonnet on identical tasks (2026-11-07)

This measures the user's "tangled mess over time" concern at the scale of single
edits, using data we already had: round-1 `comment-edit` runs, with 360 attempts per
writer model on the same 20 cases. Reproduce with:

```text
python -m evaluation.skill_eval.churn .claude/hillclimb/comment-edit-sonnet-regraded .claude/hillclimb/comment-edit-haiku-regraded
```

**Method.** The end state of each attempt is rebuilt from its stored diff. Comments,
docstrings and formatting are removed through an AST round-trip, and changed code
lines are counted against the case's original files. The minimal reference change
gets the same count. *Excess* = attempt minus reference.

| Writer | Arm | Pass | Mean excess code lines | Attempts with ≥3 excess lines |
| --- | --- | ---: | ---: | ---: |
| Sonnet 5.5 | no skill | 0.82 | −0.35 | 3/60 |
| Sonnet 5.5 | five skill arms | 0.83–0.93 | −0.43 to −0.20 | 0–2/60 each (3/300 total) |
| Haiku 5.5 | no skill | 0.85 | +0.50 | 10/60 |
| Haiku 5.5 | five skill arms | 0.73–0.83 | −0.02 to +0.53 | 6–10/60 each (43/300 total) |

**Findings.**
- **At similar pass rates, Haiku rewrites more code than the task needs far more
  often.** Across all arms that is 53/360 Haiku attempts against 6/360 for Sonnet
  (two-sided Fisher p ≈ 3×10⁻¹¹; reps within a case are correlated, so the true
  uncertainty is larger). With no skill, it is 10/60 against 3/60 (p = 0.075).
- **The skills do not reliably reduce it.** Haiku's no-skill arm scored 10/60 and its
  best skill arm 6/60 (p = 0.42).
- **What the excess looks like** (Haiku, no skill, all attempts passed the tests):
  - *Reinventing instead of adapting.* The existing regex validation was replaced
    with a hand-rolled character checker (+11 lines).
  - *Unrequested restructuring with silent behaviour drift.* A new `_display_name()`
    helper stopped trimming whitespace that the original trimmed. The tests did not
    catch it, and it happened in 2 of 3 independent runs.

**Limits.** These are single edits on small synthetic modules, not accumulation
over many changes. Excess is a proxy, since some refactoring is legitimate. There
are 20 cases, and the cost of the churn later (does it cause downstream failures?) is
not measured here. The long-horizon question is in #35 (R5).
