# Reading list access

This note covers every book, paper, and essay from the code-comments reading list. Files we could legally download are already in `docs/books` and `docs/papers`. Everything else is listed below with a legal way to read it: an official sample, an Internet Archive or Open Library loan, or a publisher page.

Start here for comments research: `docs/papers/knuth-literate-programming-1984.pdf`, `docs/papers/parnas-clements-rational-design-process-1986.pdf`, and the two Fowler essays in `docs/papers`. For the modern rebuttal to *Clean Code*, see the Ousterhout extract in `docs/books`. For documentation practice at scale, open `docs/books/software-engineering-at-google/toc.html`.

## Already in this repo

### `docs/books`

| File | What it is |
| --- | --- |
| `The Pragmatic Programmer.txt` | Full text you already had here, by David Thomas and Andrew Hunt (1999; 20th Anniversary Edition 2019). Craft habits; the book Matt Pocock recommends. |
| `software-engineering-at-google/` | Full HTML book by Titus Winters, Tom Manshreck, and Hyrum Wright (2020), downloaded from the [official free edition](https://abseil.io/resources/swe-book/html/toc.html). Licensed [CC BY-NC-ND 4.0](https://creativecommons.org/licenses/by-nc-nd/4.0/). Open `toc.html` in a browser. Chapter 3 and the documentation material are the most relevant parts for comments. |
| `ousterhout-philosophy-of-software-design-2nd-ed-extract.pdf` | Author-posted extract from the 2nd edition (2021) of John Ousterhout's *A Philosophy of Software Design*, including his comparison with *Clean Code*. This is not the full book. Full book: [author's page](https://web.stanford.edu/~ouster/cgi-bin/aposd.php). |

### `docs/papers`

| File | What it is |
| --- | --- |
| `goldstine-von-neumann-planning-and-coding-1947.pdf` | Herman Goldstine and John von Neumann, *Planning and Coding of Problems for an Electronic Computing Instrument* (1947–48). Flow diagrams as an early way to record intent, before comments existed. |
| `ibm-fortran-704-programmers-reference-manual-1956.pdf` | IBM, *FORTRAN Programmer's Reference Manual* for the IBM 704 (1956). Early formal comments: `C` in column 1. |
| `parnas-clements-rational-design-process-1986.pdf` | David Parnas and Paul Clements, *A Rational Design Process: How and Why to Fake It* (IEEE TSE, 1986). Record design rationale (the *why*). |
| `knuth-literate-programming-1984.pdf` | Donald Knuth, *Literate Programming* (*The Computer Journal*, 1984). Treat the program as an essay for people. |
| `fowler-code-as-documentation-2005.html` | Martin Fowler, [Code As Documentation](https://www.martinfowler.com/bliki/CodeAsDocumentation.html) (2005). Code is the main documentation, not the only documentation. |
| `fowler-beck-design-rules-2015.html` | Martin Fowler on Kent Beck's design rules, [Beck Design Rules](https://www.martinfowler.com/bliki/BeckDesignRules.html) (2015). "Reveals intention": put meaning in the code itself. |
