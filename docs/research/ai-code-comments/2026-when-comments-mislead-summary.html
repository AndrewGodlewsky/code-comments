What the accessible sources support

The abstract describes an empirical investigation of obsolete comments in code completion. It reports that comments can pull generated code toward an earlier implementation: an output may appear plausible overall yet fail where behavior has changed. The reported impact varies with function-signature length and task complexity. The abstract gives neither numerical effects nor model identities. Conference abstract

The author’s announcement adds a specific comparison: outdated comments improved overall similarity relative to no comments while reducing correctness in changed regions. Practical transfer: inference, not a tested remedy

A useful review question: does the generated implementation satisfy the current change, or merely resemble code that used to be right?

For a project such as BookConnect, a cautious application would be to check nearby comments whenever a behavior changes and give the assistant explicit, current acceptance criteria. A focused regression example should distinguish the new behavior from its predecessor. These are proposed engineering practices; the accessible material does not establish that they eliminate the reported failure mode.

A local evaluation could compare otherwise identical completion prompts containing the old comment, a corrected comment and no comment. Score the changed behavior separately from surrounding code similarity, record the exact model and date, and repeat generation enough to inspect variability. This would test transfer in our setting without treating a qualitative abstract as an expected failure rate.

Do not use this brief to justify deleting all comments or ranking models. The responsible takeaway is a hypothesis worth checking locally; quantitative confidence and any claimed mitigation must wait for the full paper.
