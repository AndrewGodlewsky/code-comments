Talking to Itself While Coding

Correct solution hints help weaker code generators. Asking those models to write more comments does not reliably produce those hints. The useful ingredient is accurate, task-specific information, rather than comment volume alone.

Dangfeng Pan, Zhensu Sun, Cenyuan Zhang, David Lo and Xiaoning Du · arXiv v1, 8 September 2026 · Review covers all 25 PDF pages.

What the study asks

When a model writes comments before code, those comments become context for its next tokens. Does their presence help, or does help depend on what they say? The authors distinguish naturally self-emitted comments from comments supplied by a stronger model. The latter are an experimental instrument: they inject information the weaker model might not discover itself. They are not a direct measurement of ordinary self-commenting. §1, p. 2

How the experiment separates information from appearance

First, the authors measure comment amount, placement and intent against success. Then stronger sources produce solution code preceded by comments. Only the leading comment block is extracted; executable source code is discarded. The recipient continues from that block as an unfinished assistant response.

Conditions include source comments accompanying passing or failing solutions, shuffled correct comments, unrelated-problem comments and length-matched random text. Each comparison uses a baseline on the same problem subset with the same prompt. A particularly useful control minimally corrupts correct comments on the same problems, preserving approximate length, tone and layout. Another rewrites correct hints without changing their meaning. §4.1, pp. 5–6; Appendix B.1, p. 12

Reading the numbers: pass@1 is the fraction of problems whose single generated solution passes the tests. A rise from 53.6% to 70.8% is 17.2 percentage points, approximately a 32% relative increase. This review uses percentage points for accuracy differences; the paper often prints these differences with a percent sign. Paired tests compare changed outcomes on the same problems; multiple-comparison corrections reduce false positives across many comparisons.

What the results establish

  1. Comment style is a poor universal quality signal. Among 16 models scoring at least 80%, comment tokens range from 0.1% to 71.4%. Across 13 models, the relationship between rationale comments and success is positive (Spearman ρ = 0.61), but its raw p = 0.027 misses the corrected 0.0167 threshold. This is failure to establish a robust association, not proof that rationale never matters. §3.2, p. 4; Table 10, p. 18

  2. Correct external hints produce substantial gains. Across 12 source–recipient pairings, correct-source comments improve accuracy by 17.2 points on average; all 12 survive correction. Source-pass subsets contain 757 Gemini, 892 Claude and 870 Grok problems. The headline is conditional on source success, not an all-problem deployment gain. Source-wrong comments show no significant gain in any pairing. Table 1, p. 5; D.5, p. 17

  3. Changing the algorithmic claim changes the outcome. For Qwen3-8B with Gemini hints, accuracy is 53.6% at baseline, 70.8% with correct hints and 48.2% with corrupted hints. Across all four recipients, corruption significantly reduces accuracy relative to correct hints. Unrelated-topic prefixes reduce accuracy by 20.8 points on average; random prefixes reduce it by 17.9. Shuffling preserves about 68% of the correct-hint gain, suggesting much of the value resides in local facts rather than their sequence. §4.1 and Table 2, p. 6

  4. Self-prompting is inconsistent. Of 126 non-baseline model/policy comparisons, 38 are significant after correction, in both directions. Among the four recipients, only Qwen3-8B’s dense-comment policy produces a significant gain: approximately 4.4 points. The authors compare that with its 18.1-point average external-hint gain to obtain roughly 24% recovery. Suppressing comments costs Gemma 14.5 points. Neither “always comment” nor “never comment” is supported. §4.2, pp. 7–8

  5. Repository evidence is promising but weaker. Pooled Java results show 41 task–recipient pairs improving and 16 worsening with correct hints (p = 0.001). However, only one of 24 individual repository comparisons survives Holm correction: Qwen’s Java wrong-topic condition, down 13.8 points. Correct-hint gains are not individually significant. Pooling combines repeated tasks across recipients, rather than independent new tasks. Table 3 and §4.1, pp. 6–7; B.8, p. 16

Limits and unsupported conclusions

“Correct” means the source solution passes tests; it is a proxy for comment correctness, not a proof of every claim. Source-failure problems are harder and recipients already perform near zero there, limiting what the null result can show. The corruption comparison addresses this better, although only 50 corruptions were checked manually. Intent labels were calibrated against 100 snippets labelled by one author; some categories have weak agreement. §4.1, p. 5; Appendix A, pp. 11–12

The 24% recovery ratio compares self-prompting across the benchmark with external hints on source-success subsets and different baselines; it is a useful descriptive comparison, not an exact capability ceiling. One deterministic generation per condition cannot establish robustness across sampling or later model versions. These experiments do not demonstrate that all planning methods fail, that training is necessary, or that removing repository comments improves maintenance. They also do not measure human comprehension or long-running coding agents.

Practical knowledge transfer

Directly supported: Evaluate a comment policy on the particular model and task set. Output that obeys a requested style can still become less correct. Test success, rather than comment abundance, should decide whether a policy helps.

Our inference: Spend documentation effort on verified constraints, algorithm choices and edge cases. Before feeding an existing comment to a coding assistant, check that it describes the current task. A concise, accurate invariant can carry more useful information than a long generic explanation.

Our inference: A stronger-model planning stage is worth testing when it supplies missing knowledge, but this study does not establish its cost-effectiveness. Compare total cost and end-to-end success against simply using the stronger model, including the cost of detecting bad plans.
