# Offline Longitudinal Runner Implementation Plan

**Goal:** Execute bounded, isolated development trajectories with auditable records.
**Spec:** [runner design](../specs/2026-11-06-runner-design.md).
**Architecture:** Docker execution/snapshot boundary; host-owned behavioral grader;
offline trajectory coordinator. Python standard library; no model providers.

The user has authorized work across the roadmap. Root implements locally and a
fresh reviewer checks the entire branch. Corpus #8 is in a separate worktree.

1. `evaluation/sandbox.py`, `tests/test_sandbox.py`: test and implement the pinned
   Docker boundary, safe snapshots, bounded output/deadlines and cleanup.
2. `evaluation/grading.py`, `tests/test_grading.py`: independently expected values
   stay on host; execute candidate calls only in Docker; reject forged PASS output.
3. `evaluation/runner.py`, `tests/test_runner.py`: test deterministic paired order,
   temporal reference context, step artifacts, no-op failures, locks, configuration
   drift and safe resume; add diagnostic CLI and zero model-spend configuration.
4. `.github/workflows/evaluation.yml`, `docs/evaluation/runner.md`: publish tested
   commands and opt-in Docker CI, record exact limits and remaining #7 criteria.
   Update README/architecture where implemented facts change.
5. Run Python suites, actual Docker probes/replay and document checks. Push a
   verified checkpoint. Independent review determines whether #7 can close; do
   not remove unmet scope just to merge or label a partial runner complete.

Every meaningful implementation slice gets a failing behavioral test before its
implementation, then the complete relevant suite. Keep durable evidence in #7.
Retain incomplete branches with a clear handoff; close completed branch purposes
through independent review, integration, cleanup and final audit.

## Resumption: bounded tool sessions

The user requested resuming #7 and #8 after the branch audit. The unused Orca
workspace had no unique commits; its worktree and branch were removed. Both
unfinished task branches now include main's source collection.

Next runner checkpoint (root implementation, grader files delegated separately):

1. Add a small JSON-shaped command-session boundary over the existing Docker
   sandbox, with per-step call and cumulative input/output byte limits. Retain
   exact attempted commands, outputs and rejection reasons; close on exhaustion.
2. Route diagnostic adapter commands through it. Pin limits and implementation
   bytes in manifests; give each attempt a fresh session ID, preserving only
   trajectory code between steps. Resume must reject changed limits.
3. Test limits and invalid requests before execution, trace ownership, actual
   Docker integration, fresh sessions and existing pause/resume behavior.
4. Independently review and push the checkpoint, keeping #7 open: this is a tool
   boundary exercised by scripted adapters, not a real model/provider adapter,
   natural model discovery, or proof of duplicate-billing protection.

Ruling: retain the existing command tool instead of adding parallel read/write
APIs; Docker already owns filesystem/process isolation. Session limits constrain
tool execution, not arbitrary host adapter code. Provider execution stays gated.

Validation: the new session tests first failed for the missing boundary, and
runner integration tests failed for the missing pinned-limit option. After
implementation, all 51 tests passed with `CODE_COMMENTS_DOCKER=1`, including
fresh session IDs across nine oracle attempts, budget exhaustion without grading
or replay, and the existing isolation/reference/mutant checks. Grader hardening
was not implemented in this checkpoint; its existing trust limitation remains.
