# Offline Longitudinal Runner Implementation Plan

**Goal:** Execute bounded, isolated development trajectories with auditable records.
**Spec:** [runner design](../specs/2026-11-06-runner-design.md).
**Architecture:** Docker execution/snapshot boundary; host-owned behavioral grader;
offline trajectory coordinator. Python standard library; no model providers.

The user has authorized work across the roadmap. Root implements locally and a
fresh reviewer checks the entire branch. Corpus #8 is in a separate worktree.

1. `evaluation/sandbox.py`, `tests/test_sandbox.py`: test and implement the pinned
   Docker boundary, safe snapshots, bounded output/deadlines and cleanup.
2. `evaluation/grading.py`, `tests/test_grading.py`: independently expected values
   stay on host; execute candidate calls only in Docker; reject forged PASS output.
3. `evaluation/runner.py`, `tests/test_runner.py`: test deterministic paired order,
   temporal reference context, step artifacts, no-op failures, locks, configuration
   drift and safe resume; add diagnostic CLI and zero model-spend configuration.
4. `.github/workflows/evaluation.yml`, `docs/evaluation/runner.md`: publish tested
   commands and opt-in Docker CI, record exact limits and remaining #7 criteria.
   Update README/architecture where implemented facts change.
5. Run Python suites, actual Docker probes/replay and document checks. Push a
   verified checkpoint. Independent review determines whether #7 can close; do
   not remove unmet scope just to merge or label a partial runner complete.

Every meaningful implementation slice gets a failing behavioral test before its
implementation, then the complete relevant suite. Keep durable evidence in #7.
Retain incomplete branches with a clear handoff; close completed branch purposes
through independent review, integration, cleanup and final audit.
