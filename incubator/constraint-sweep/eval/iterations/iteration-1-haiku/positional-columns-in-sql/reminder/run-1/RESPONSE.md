The nightly CSV now has a `currency` column directly after `amount`. The header is `id,account,amount,currency,ts`, and currency holds the ISO 4217 code from each entry (for example `EUR`). The change is in `exporter/csv_out.py` (`COLUMNS`). `reports/monthly.py` and the finance doc are unaffected in behaviour; I added one sentence about the column to `docs/finance.md`.

One thing you need to check before the next run: the warehouse load is positional, not by header name. `deploy/warehouse/load_ledger.sql` stages each file as `c1, c2, ...` and skips the header, and its comment said new columns must go at the end. Putting currency after amount shifts `ts` from `c4` to `c5`, so I changed the SELECT to `c1, c2, c3, c5`. Currency is at `c4` and is not loaded, because `ledger_raw` has no currency column. The comment in that file now records the positions. Without that edit, `posted_at` would have received currency codes. This is a change to production load SQL that runs at 01:30 via `deploy/crontab`, so please have someone review it. If you would rather not touch the loader, the alternative is to append currency at the end of `COLUMNS` instead, which breaks the side-by-side requirement.

Tests: I added two cases to `tests/test_csv_out.py` (currency is next to amount, and is written as given). All 8 tests pass with `python -m unittest discover -s tests -t .`.
